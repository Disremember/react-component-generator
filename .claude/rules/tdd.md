# TDD Rule

> **경고: 이 규칙은 Rigid다. 상황에 맞게 변형하지 마라.** 적용 대상이면 예외 없이 RED-GREEN-REFACTOR를 따른다.

## 0. 우선순위

- 프로젝트의 `CLAUDE.md` / `AGENTS.md`에 TDD 규칙이 있으면 **그 규칙이 우선**한다.
- 이 파일은 프로젝트 규칙이 없을 때 적용하는 **기본값(fallback)**이다.
- 테스트 실행 명령은 프로젝트 문서의 명령을 따른다(이 저장소: `bun run test`, 단일 파일 `bun run test -- <path>`).

## 1. 적용 기준

**TDD 필수**

- 비즈니스 로직 (조건 분기, 계산, 상태 전이)
- API (요청 검증, 응답 형식, 에러 처리)
- 유틸리티 / 순수 함수
- 버그 수정 (버그를 재현하는 실패 테스트부터 작성)

**TDD 불필요**

- 타입 정의 (`interface`, `type`)
- 설정 파일 (빌드, 린트, tsconfig, 환경 설정)
- 순수 UI (로직 없는 마크업·스타일)
- SQL (스키마, 마이그레이션, 쿼리 정의)

판단이 애매하면 **필수로 간주**한다. 순수 UI라도 조건부 렌더링·이벤트 처리 로직이 있으면 그 로직은 필수 대상이다.

## 2. RED-GREEN-REFACTOR

### RED: 실패하는 테스트

- **하나의 동작 = 하나의 테스트.** 한 테스트에 여러 동작을 검증하지 않는다.
- 테스트 이름은 검증할 동작을 문장으로 쓴다.
- **반드시 실행해서 실패를 확인한다.** 실행하지 않은 테스트는 RED가 아니다.
- **실패 이유가 "기능 미구현"이어야 한다.** 문법 오류, import 오류, 오타, 잘못된 테스트 설정으로 인한 실패는 RED가 아니다. 테스트를 고쳐 올바른 이유로 실패할 때까지 다음 단계로 가지 않는다.
- 작성하자마자 통과하는 테스트는 아무것도 검증하지 않는다. 테스트를 재검토한다.

### GREEN: 통과시키는 최소 코드

- 방금 실패한 테스트를 통과시키는 **최소한의 코드만** 작성한다.
- **YAGNI**: 아직 테스트가 요구하지 않는 분기, 옵션, 추상화, 확장 포인트를 넣지 않는다.
- **신규 테스트와 기존 테스트가 모두 통과**하는지 전체 테스트를 실행해 확인한다.
- 기존 테스트가 깨지면 GREEN이 아니다. 테스트를 수정·삭제해 통과시키지 않는다.

### REFACTOR: 구조 개선

- 대상: **중복 제거, 이름 개선, 헬퍼 추출.**
- 매 변경 후 테스트를 실행해 **green을 유지**한다.
- **새 동작을 추가하지 않는다.** 새 동작이 필요하면 RED로 돌아간다.
- 테스트 코드도 리팩터링 대상이다(중복된 준비 코드 등).

### 반복

- 다음 동작에 대한 **RED로 돌아간다.**
- 남은 동작이 없을 때까지 사이클을 반복한다.

## 3. 삭제 강제 규칙

- 테스트보다 프로덕션 코드를 먼저 작성했다면 **그 코드를 삭제하고 RED부터 재시작**한다.
- **"참고용"으로 남기는 것도 금지**한다. 주석 처리, 별도 파일·브랜치 보관, 스크래치 복사 모두 포함한다.
- 이미 존재하던 코드를 수정하는 경우에도 동일하다. 변경분을 되돌리고, 변경할 동작에 대한 실패 테스트부터 작성한다.

## 4. 변명 차단표

| 변명 | 반론 |
|------|------|
| "너무 단순해서 테스트 불필요" | **단순하면 테스트도 1분이다.** 단순한 코드일수록 경계값·null·빈 입력에서 깨진다. 비용이 작으니 생략할 이유도 없다. |
| "나중에 추가하겠다" | **나중은 오지 않는다.** 구현 후 작성한 테스트는 코드에 맞춰 쓰여 실패를 본 적이 없고, 무엇을 검증하는지 보장하지 못한다. |
| "시간이 없다" | **디버깅과 회귀 수정이 더 오래 걸린다.** TDD는 작은 단계로 나눠 오히려 되돌아가는 시간을 줄인다. |
| "삭제하면 낭비" | **매몰 비용이다.** 이미 쓴 코드는 다시 쓰면 더 빠르고 더 좋아진다. 테스트 없이 남긴 코드가 더 큰 비용이다. |
| "프로토타입이다" | **프로토타입은 그대로 프로덕션이 된다.** 정말 버릴 코드라면 적용 대상 저장소에 커밋하지 않는다. 남길 코드라면 TDD 대상이다. |
